# Culture commands — initial slice

All endpoints are authenticated POSTs with the existing JSON envelope, body limits and principal binding. A supplied `binding.principal_id` must match the authenticated principal; omitting it uses that principal. Actor control is checked again in storage, including exact retries.

Each request includes named `binding` with `instance_id`, `branch_id`, `expected_head`, `idempotency_key`, and optional authenticated `principal_id`. Retry the original complete request to retrieve the original record; a changed request with the same key is rejected. A new command requires the current branch head and no unfinished RP action. Results are immutable `CultureRecord` snapshots with event ID, sequence, world time, typed fact and replay flag.

| Endpoint | Additional request fields | Authority and evidence |
| --- | --- | --- |
| `/api/v1/culture/define` | `author_id`, `culture` | Control author; community requires matching scope/culture ID, organization current managerial authority, family confirmed membership, world/region an active dedicated scope grant. Server assigns version Event. |
| `/api/v1/culture/territories/define` | `scope_kind: world/region`, `scope_id`, `steward_id`, `place_ids` | Explicit world-pack setup by an active creator retaining the branch's genesis-backed Cohort construction grant. World ID must match instance and has no place list; region requires 1–64 distinct real active scoped places. |
| `/api/v1/culture/territories/authority` | `scope_kind`, `scope_id`, `decision: revoke/appoint`, `steward_id` only for appoint | Same scoped builder authority; records a new authority Event and atomically projects this scope's grant. |
| `/api/v1/culture/transmit` | `speaker_id`, `definition_event_id` | Control speaker; actual author or someone who heard this exact version. Current co-location determines recipients. |
| `/api/v1/culture/internalize` | `entity_id`, `stance`, exactly one of `transmission_event_id` / `definition_event_id` | Control actor; transmission must actually include them, or definition must actually be authored by them. |
| `/api/v1/culture/affiliate` | `entity_id`, `definition_event_id`, `decision: join/leave`, optional `transmission_event_id` | Control actor. Join requires authored or actually heard definition; organization join additionally requires effective own employment in that organization. Leave requires active own affiliation and no new transmission. |
| `/api/v1/culture/families/propose` | `family_id`, `proposer_id`, `invitee_id` | Control proposer; distinct existing scoped individuals must actually be co-located. Records a chosen-family proposal, not an accepted family. |
| `/api/v1/culture/families/accept` | `entity_id`, `proposal_event_id` | Control the exact invitee. Commits their separate confirmation once; does not accept any cultural norm on their behalf. |

Culture fields: `culture_id`, `version_event_id`, `scope_kind`, `scope_id`, `values`, `norms`, `customs`, `taboos`, `rituals`, `status_symbols`, `group_identity`, `subculture_of`, `transmission`, `conflict`, `evolution`. Initial executable norm has `norm_id`, `action: "gift"`, and `evaluation` from -2 to 2. Descriptive fields are not a prompt-to-execution language. Complete definitions must fit the existing 2000-byte speech bound to be transmitted; oversized transmission fails atomically. Norms/descriptions have additional core validation bounds.

Stance is `accept`, `partial`, `oppose`, or `rebel`. Defining, hearing, or being an author never automatically creates a stance or group membership. Authored internalization stores `knowledge_kind: "authored"`, the actual version Event and an empty transmission ID. Heard internalization preserves its actual transmission source. No self-listener, fabricated speech, new authority grant, money transfer or public outbox is created by internalization.

Version evolution uses `/culture/define` with `previous_definition_event_id` equal to the current version. The author must know that version, retain scope authority, and preserve culture/scope identity. Community revisions belong to the existing author; others may form subcultures. First definitions omit the previous source. No version update silently alters recipient knowledge or stance. Old exact requests retain original results; stale new revision requests fail.

For subcultures, `parent_definition_event_ids` must match `culture.subculture_of` in order (at most eight unique parents), each pointing to an actually authored/heard definition. Self-parenting and duplicate parents are rejected. Lineage pins older immutable versions; it does not recursively auto-adopt all parent norms. Opposite own sourced norm evaluations retain a bounded list of conflict index pairs in `Life.CultureExperiences` (up to eight pairs; complete evaluations remain retained). Conflict evidence is private to the evaluator and does not force a universal resolution.

Affiliation is independent of normative acceptance. Creating a community, hearing its definition or accepting/rejecting its norms does not join or expel anyone. Join/leave/rejoin are explicit sourced Events. Current own `Life.CultureAffiliations` includes the latest joined/left record per culture, ordered by culture ID; departed membership retains its history. Exact retry returns the old immutable result without reapplying membership. Community affiliation neither gives organizational authority nor invents kinship/employment.

Organization definitions retain `scope_source_event_id`. Organization affiliation retains `employment_contract_id` and `eligibility_event_id` proving eligibility **at joining**, not perpetual employment. Onboarding-only future contracts do not qualify. Cultural affiliation is not the employee roster: subsequent job departure is governed by employment Events and does not automatically erase cultural identity. Culture creates no capability grants or financial effects. Managerial authorization is checked before definition retries; revocation cannot be bypassed by replaying an old key. A former manager can still remember and relay previously authored culture; remembering is not current managerial authority.

`family` definitions are also supported: `scope_id` references a mutually confirmed chosen-family declaration, and author must be one of its two explicit participants. The acceptance Event is retained as scope source and as family-affiliation eligibility. Proximity, names, housing and heard norms never substitute for that declaration. A family member may separately join and oppose/rebel against its culture. Outsiders may hear/evaluate a family's norms without gaining family membership. This initial declaration models chosen family only; it is not a genealogy, marriage, inheritance or legal-guardianship engine and grants no control over either participant. Family expansion/dissolution is not implemented here.

World/region setup records actual builder and place-definition sources and grants only `world.culture.define` in existing capability tables, bound to `world:<id>` or `region:<id>`. It grants no RP control, money, law-enforcement or managerial rights. The appointed actor authors and actually transmits definitions; configured world culture is not universal NPC knowledge. Regional affiliation requires current presence in a listed place and retains the presence Event/place plus territory source. It describes cultural identity acquired there, not proof of permanent residence or current location. Being present is not itself joining or accepting norms. Setup is explicit, never a hidden bootstrap change.

There is no global read-all-cultures/stances endpoint in this slice. A private retry remains actor-authorized. NPC decisions receive only their own cultural experiences/affiliations. Scope grants are checked against the latest installation or authority-change Event, not merely the current row. Compare/Rebuild reconstructs the latest sourced active/revoked status and steward, retaining legitimate revocation even after grant deletion or stale-row corruption. Manual projection edits remain corruption, not world actions. A replaced steward loses definition authority but retains previously authored/heard knowledge. Evolution and laws remain pending.

Validation: actual HTTP authentication/mismatched-principal/actor-control checks, author versus recipient knowledge, private retry isolation and exact retries across SQLite/server reopen. Core/storage integration separately covers real cultural gift evaluations and committed NPC choices; HTTP coverage alone does not prove the full RP-4 stage.
