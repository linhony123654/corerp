# RP-4 institution/law implementation boundary

Status: installation/proposal/future enactment, knowledge/choice, witnessed violation, conserved fines, private defendant dispute/review/refund, versioned amendment/repeal, sourced institutional role lifecycle/recovery and explicit defendant-led pending-dispute handover implemented. APIs, remaining enforcement boundaries and full stage acceptance remain incomplete. Increment sections below preserve historical limitations; later sections supersede their pending items.

The first law governs actual speech (`speak`, corresponding to NPC `respond`/`refuse` and player accepted speech) in an explicitly installed world/region scope. Silence/wait/movement remain technically executable. This is a configurable fictional norm, not a universal morality or a new prose interpreter. Existing RP `LegalActions` continues to mean execution eligibility; normative lawful candidates and actor-known law versions are separate views.

Institution installation is an explicit builder action. It references an existing territory and funded organization treasury, and grants separate scoped legislative, enforcement and review capabilities to existing actors through the current ACL. Cultural stewardship does not grant any of these. No money or person is created. Actor control plus the relevant role is required for role commands, including retries.

Ordered implementation: installation/roles → actor proposal → authorized enactment with strictly future effective time → actual propagation → own-known lawful candidates and choice → actual sourced violation → separately authorized enforcement → actor dispute/review → amendment/repeal. Enactment snapshots are immutable. Current authority selects the latest effective version using the existing world clock; agent belief uses only actually heard versions. Future and unseen versions must not take early effect or silently update belief.

Enforcement is not automatic. It must identify an actual scoped act committed while a norm was effective and a separately authorized procedure. A bounded fine transfers real available funds to the existing treasury through the existing ledger with conservation/rollback; no narrative penalty or fabricated balance. Dispute and review are separate sourced Events, with any reversal limited to actual collected funds. Detailed procedure/violation schemas must be verified against the real commit/ledger paths before implementation.

Acceptance remains original RP-4: proposal/enactment/effect, separate law and obedience, authoritative versus known versions, deliberative noncompliance without ACL bypass, sourced consequences/dispute, propagation of amendments/repeals, recovery/authorization/conservation and all six direct culture/law-agent checks. A law table or green pure evaluator is insufficient. No publication/deployment is required or authorized.

## Witnessed violation and separate enforcement increment

`RecordRPLawViolation` requires a controlled enforcer with institution-scoped sourced enforcement role. It references actual immutable `RPSpeechAccepted` actor/place/time/listener evidence; the enforcer must have heard the act (or be its speaker) and know the cited enactment. Applicability is checked at the act's original time/place, not report time. Non-speech effects, pre-effective acts and a second case for the same act/enactment are rejected. Recording does not punish.

`EnforceRPLaw` is a separate authorized command. In this first procedure the same recording enforcer handles its known case; role alone does not grant knowledge of every private case. It applies the enacted fixed fine to a real active individual account and the institution's existing treasury, same currency, actual available funds and safe integer bounds. Insufficient funds fail rather than creating money or an unmodeled debt. Zero fine records enforcement without a journal. Positive fine uses the existing posted double-entry journal/account projections in the same private command transaction. Duplicate enforcement is rejected; exact authorized retry returns its original effect.

The real law-choice test now follows deliberately committed speech through witnessed violation, authorized fine, exact balanced postings, duplicate rejection, injected rollback and reopen/rebuild/exact retry. It also proves no retroactive charge, no silence-as-speech, no automatic fine on violation record, and reviewer role cannot enforce. This supplies a real consequential noncompliance path, not yet full dispute/review or all speech-source coverage. Current evidence path covers accepted RP speech; dedicated announcement-domain events need explicit applicability review before claiming universal coverage.

## Version lifecycle contract

Amendment/repeal reuse proposals and enactments, adding optional predecessor and repeal markers. Proposal authors must actually know the predecessor. Enactment compares that predecessor against the latest committed version (including future versions); effective times must strictly increase and remain future relative to the command. A repeal is an explicit version, not deletion or a zero-fine prohibition. Historical evaluation selects the latest effective version at the original act time. Belief evaluation uses the same selection algorithm over only actually known versions, retaining old terms until a new announcement is heard; hearing an older version later cannot regress that belief. Future versions cannot prematurely suppress the current version. Test acceptance includes stale proposals, unknown predecessors, effective boundaries, propagation and recovery. No existing penalties are automatically erased or refunded by a repeal.

Implemented with optional `previous_enactment_event_id` and `repealed` fields, preserving legacy omitted-field hashes. Proposals use full bounded law terms and an explicit repeal marker; a zero fine alone still means a prohibition. A later non-repealed successor can explicitly re-enact terms under the same version/CAS/time rules. Scope remains institution-defined. `EffectiveRPLaws` selects the latest effective supplied version per institution/law before filtering repeals and places; the authoritative reader supplies enacted history while the actor context supplies only authored/heard history. No source-reader sharing makes hidden versions known.

It changes one of the three installed offices through `revoke` or `appoint`, retains its stable grant ID and stores the prior authority Event, role identity/principal, current status and builder source. ## Explicit pending-dispute handover

`ForwardRPLawDispute` lets the original affected actor resubmit the existing private filing to the current active reviewer. It rechecks actor control and filing ownership before retries, records dispute/recipient/authority sources, rejects final cases and duplicate receipts, and changes neither money nor case decision. This is explicit delivery, not permission for office holders to search every private filing. Review requires an original addressed filing or this sourced delivery plus current office authority and disinterested identity; forwarded review retains `receipt_event_id` as provenance. Receiving a filing does not make the recipient a role holder, and losing office still prevents review.

The actual fine/dispute test now replaces an interested reviewer with independent Ada: office appointment alone cannot reveal the case; another actor cannot forward it; injected failure leaves it unreadable; the affected actor's real handover survives reopen/rebuild/exact retry; the successor then completes the existing rollback-safe conserved refund path. Duplicate handover and forwarding a final case fail. This closes pending review succession without implicit institutional omniscience. Delegation of an un-enforced violation to a different enforcer remains outside this command; its current same-recorder rule is unchanged.
