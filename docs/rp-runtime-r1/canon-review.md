## 审阅与重放记录

作者确认后，将其另存为带版本和来源的新世界声明，用**当前 R1 runtime** 在相同可用模型配置下重放 G1–G8，检验“关系已声明时是否真正影响决策”。结果另存新文件，逐项记录声明哈希、模型标识、每个场景的输入、事件 head、决策与叙事回执；不得覆盖冻结的 before/after，也不得把不同世界输入的输出直接当作运行时性能对照。

重放入口是 `node scripts/verify-rp-runtime-r1-golden.mjs --spec-file /path/to/authored-world.json`（在项目根目录运行，沿用 Golden 所需的模型环境变量）。新声明必须保留冻结世界的地理、角色键/名称/初始位置和其余基础字段；脚本只允许增加角色人设、公开风格、日程、熟人及定向关系/称呼。产物写入新建的临时目录，标记 `label: "authored"` 并记录实际声明的 SHA-256；脚本拒绝将 `--spec-file` 与冻结样本的 `--after` 标签混用。这个入口只负责隔离重放，**不会**把填写中的审阅单当作设定，也不会改写预览世界。

冻结的旧 runtime 二进制（SHA-256 `fea2067aa393dd6608b5502f13a7ee3884d5ba5336203d167de315a99a4cbc23`）的 `StudioWorldSpec` 尚无 `persona`、`public_presentation`、`acquaintances`、`relationships` 字段，HTTP JSON 解码拒绝未知字段，因此**不能**直接接收新的作者声明。若要做“同一新输入下的旧决策/新决策”因果比较，需另建只补数据入口、保持旧决策/叙事逻辑的兼容对照运行时，并明确标记其不是原始旧二进制；在此之前，新增设定的重放只能算 R1 的关系就绪产品验证，不算冻结 old/new 的同输入对照。

真人审阅每个 G1–G8 场景时，按[固定 rubric](golden-baseline.md)记下：前后各一句代表性原话与事件来源；身份、人设、关系/称呼、知识边界、上下文连续性、NPC 意图、自然度、叙事表现、下一轮 observable 连续性各项的 0–2 分或 `N/A`；每个 0/2 的一句理由；“是否愿意继续玩”及原因。没有源设定的维度只能记 `N/A`，不能给模型猜中原著的回答加分。
