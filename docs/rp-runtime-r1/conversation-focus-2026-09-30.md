# 公开交流对象延续 · 2026-09-30

本增量在现有激活计划内完善未点名回合的对象延续，不建立对话世界状态，不读取 NPC private，不改 typed owner。上一增量已经完成并通过完整后端测试；本次源码变化需要独立验证。

## 验收与设计

- 当前明确点名优先，其次是上一轮实际公开交流对象，最后才是稳定顺序。
- 延续来源必须是同世界/分支、同受控观察者上一条已接受玩家发言的 NPC 回复，并有该玩家当时实际听见的冻结观察；未提交 proposal、私有意图、旁人的交流和没有听见的回复不成为依据。
- 多人实际回复时，只在已有固定计划明确选择了一个点名/延续对象，且该对象确实回复的情况下延续；歧义保留稳定回退。
- 场所变化、玩家离场或该玩家确实目击的NPC离场、章节边界或超过30分钟的世界时间不保留激活偏好；历史内容仍可由原 context builder 检索。
- 当前仍需通过实际听者和控制者检查。deterministic 模式保持其定义；legacy 保留全部听者记账和调用数，但允许按公开交流优先级调整调用顺序。不能用兼容模式绕开真实旧世界的体验改进。
- 延续的来源 Event 在原激活表内随 rank/reason 固定，重试和重启加载原计划。增量迁移保留旧行，不改写历史计划或世界 Event；外部控制接管必须清除延续元数据。

先用合成作者配置做确定性的多角色回归，覆盖明确切换、另一客户端、未知姓名、未听见、角色离场/返回、章节、歧义、重启/重建、接管与旧计划迁移。之后做相关测试与全包回归。实际32轮此前因超时失败，本增量不靠原样盲跑证明稳定性。冻结Golden和作者canon/真人评审仍独立验收，不能把确定性对象选择当作趣味性通过。

## 实现边界

`readRPConversationFocus`只读已提交台词和该观察者的冻结听觉记录，以及原激活计划的公开选择依据。上一条自己的玩家发言对应的实际NPC回复可延续；自己等待回合内确实听见的NPC主动开口也可以开启交流。多人回复只有唯一最强既有选择才能延续（点名高于旧延续），同级歧义不选任意最后说话者。旁人的交流不会成为“我”的交流对象。

原激活表076迁移增加 nullable来源Event外键与`conversation_continuation`原因；只有activated延续行允许且必须有来源，接管清除来源和rank。旧行逐列保留、来源为NULL；重试加载固定计划。没有新增角色关系、记忆状态或世界事件。

英文短名采用词边界，避免Bo在book或Ann在Anna内误命中；这仍是词法提示，中文提及与真实称呼的语义歧义没有被宣称解决。30分钟世界时间只是激活偏好的过期政策，不删除旧史、不判断感情。

新增回归用合成作者配置覆盖：未点名接续及明确切换、模式调用预算、陌生人姓名保密、另一个客户端、故障后重启/重建、章节/世界时间/自身与目击离场、未听见与未提交私有草案、旁人交流、主动开口、多人歧义、真实控制者接管以及有旧计划的075→076迁移。授权负例发现Studio不能用普通player grant接管另一角色；测试改走原service控制者登记/接管/释放，未弱化权限。


## 接下来的R1工作（本增量没有实现）

原`BuildRPDecisionInput`还分别装配16条近期发言、40条玩家话摘录、20条非台词知识、3条本人过去私有决策、最多4组/6000字符的相关旧对话，以及自身动作等视图；没有共同的优先级和总预算。下步应在原builder内完成确定性选择，保留人设/关系/称呼、当前刺激、时间/场景、readiness和所有必要出处，再选择近期与相关历史，明确记录因预算省略的内容。adapter的128KiB拒绝上限不能代替装配策略。

去重不能机械地“同一个Event只留一条”：一个角色声明Event可以含多个不同关系，一个已提交决策也可能同时支持NPC本人的私有决策记忆和公开台词。应按来源加事实身份去重，只消除重复内容；private与observable保持各自权限。被裁剪的原话不得冒充完整原话，长对话样本必须验证前段关键信息能够带出处恢复。

对Step超时先测请求/字段大小、实际输出预算和耗时，诊断只导出长度、数量、固定失败类别，不记录私有正文或凭证。当前两轮小样证明对象连续，没有证明缩短请求能修复超时，也没有重新通过完整32轮。冻结Golden的作者数据缺失和真人评价依旧独立处理，不借模型常识补设定。
