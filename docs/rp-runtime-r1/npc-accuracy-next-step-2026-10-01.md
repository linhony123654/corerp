# NPC 准确度：下一处结构性修改

这属于尚未完成的 R1，不是另开 R2。当前完整前后样本及独立审计证明：世界会正确记录角色说过的话，但 v3 私有 `basis_event_ids` 只检查来源存在/获准/不重复，不检查自由对白内每个命题。新 renderer 忠实显示原话，所以无法修复角色自己补写的经历或状态。

最小可推进方向是在唯一 Context Contract/决策 adapter 上明确出处的**支持范围**，无需添加世界状态、summary memory 或更多 owner：

| 获准来源 | 能支持什么 | 不能据此确认什么 |
|---|---|---|
| 作者 persona / 关系声明 | 已声明身份、特征、角色关系与称呼 | 原著情节、未声明的共同过去与惯常经历 |
| 真实观察 / typed action | 具体时点的获准 observable、完成结果 | 未见后续、另一角色的 private state |
| 自己说过 / 亲耳听见 | 谁在何时说了什么、提出过什么愿望或约定 | 话语内容都为真、承诺已兑现、邀请已经执行 |
| 自己的旧私有 sketch | 原时点和原对话者下的动机/情绪 | 永久目标、别人的态度、姿态或天气事实 |
| 当前玩家语句 | 当前请求、玩家明确报告的状态或纠正 | 未提到的玩家表情、站坐、动机和过去 |

不要再把所有来源压成语义上等价的 handle 列表。沿现有 packet 产生 server-bound 的来源类别/时点/适用对象；对需要引用既往事实的 assertion 增加可检查支持范围。模型提供的 claim manifest 可以辅助 diagnostics，确定的类别/引用越界可硬拒绝，无法证明文本包含哪些命题则必须标为 soft/人工。

范围与限制必须真实：自由对白的模型可以漏报某个命题，manifest 完整性不能靠另一个普通模型或哈希保证。只有将某一事实陈述类别改为服务器从获准 reference 实现，才有该类别的硬保证。不能把所有对白改为封闭模板，也不能硬禁比喻、人物观点、假设、未来承诺或可识别的疑问。

下一次修改先用同一已授权状态演示最小真实片段，检查当前记录支持范围、没有执行动作却被说成已完成的前提、修正后是否仍复述错误。保留失败稿；不逐句增加“贾母不要…”特例、不临时补出坐下/天气/童年 canon，也不靠清空正确历史掩盖回忆反馈。确认改动改善具体输出后，再重开受影响的技术与 Golden gate。

证据：`product-golden-after-2026-10-01.json` 第3/4/7/8/14–22轮；`audits/product-implementation-review-2026-10-01.md` 完整对照；`core/rp_proposal.go` 的私有来源验证与 speech 长度/字段验证。审计没有证明模型实际依赖了哪个输入（目前只存 input hash，未存完整 private provider packet）；不要把可能的反馈路径写成已证实的因果。
