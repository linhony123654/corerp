# RP integration architecture audit — 2026-10-01

The strongest explanation for inaccurate RP after kernel work is a mismatch between the claimed experience and the actually exercised contract: missing authored input blocks NPC calls, recorded preview delivery lags tested code, and legal sourced speech is not semantically verified speech. This inspection demonstrates no new deterministic kernel implementation bug at HEAD; it does identify partial guarantees and an observed provider-fallback loss of reply. Persistent goals are not established as the next required fix.

## Scope and confidence

- Audited repository HEAD `739a3ad94f34dd1d7a0a4cf1ec450ea02514415e` by local source and checked-in public evidence inspection. Read project `AGENTS.md`; existing dirty planning files and screenshots were left untouched.
- This is an independent audit, not a new execution result. No provider calls, installs, tests, deployments, commits, or plan/code edits were made. Only this report was created. File references below are repository-relative with line numbers at the audited HEAD.

### B. “Grounded” decisions still permit unsupported implications in accepted dialogue

**Classification:** demonstrated semantic-contract limit, not a demonstrated failure of typed effect validation. **Trigger:** a model produces plausible role-specific speech carrying an undeclared prior event. Public short sample line 45 accepts “身子可好些了？”; fixture lines 69–77 contain no illness declaration. The words are observed; interpreting them as implied illness is a human semantic inference.

**End-to-end trace:** explicit persona/relationship → same builder and masked provider view → adapter tells model to use canon → `core/rp_proposal.go:19–31` checks private bounds and ID membership (empty basis is legal), lines 48–53 reject a narrow explicit self-introduction conflict, lines 65–69 check speech shape/size → storage validates actual provider input and canonical input (`rp_decision.go:510–513`) → commit rechecks fresh head/hash (`rp_decision_commit.go:51–63`) → renderer preserves the accepted utterance. There is no entailment check proving that its claims follow from cited records. `decision/reply_quality.go:10–23` checks format/repetition, not illness/backstory consistency. Prose quote checking cannot fix inaccurate accepted speech without rewriting authority.

**Minimal repair:** narrow any “grounded/consistent” promise to provenance, lawful effects and the specific deterministic identity rule actually checked. Add this exact public sample to semantic review on a fixed authored fixture. Where a factual premise is not supplied, instruct the decision adapter to ask a neutral present-tense question rather than assume past illness; evaluate that prompt change on held-out authored questions before claiming success. This is a proposed bounded instruction/experience repair, not a semantic proof or automatic hard reject. Do not add an illness fact, require arbitrary nonempty IDs, or block all ordinary questions with a regex. **Risk:** overly cautious instructions can make dialogue sterile; test naturalness and truthful premise separately. Source IDs remain provenance only. No new world owner is needed.

### C. Provider failure yields a durable silence that resume cannot replace

**Classification:** demonstrated partial recovery contract and intentional current fallback policy; not ledger corruption. **Trigger:** provider timeout after some actors have replied. Recorded original 32 fails at round 29 (`scene-activity-context-verification-2026-10-01.json:904–911`); timeout occurred despite 86 successful NPC decisions.

**End-to-end trace:** provider receives a valid packet → all attempts share `decision/chat.go:186` timeout → storage emits `provider_fallback` silence (`storage/rp_decision.go:489–508`) → commit explicitly permits it (`rp_decision_commit.go:41,65–66`) → `rp_turn.go:172` commits it → later resume skips any already committed decision (`rp_turn.go:148–153`). Public receipts distinguish failure, but the missing reply is now a world stance for that turn. This is exactly-once recovery, not reply recovery. No evidence shows the provider timeout was caused by missing memory or a wrong owner.

**Minimal repair:** first accurately expose interrupted-versus-chosen-silence status using existing receipts and verify current UI handling; this audit has not demonstrated a UI concealment bug. If product behavior requires recovering the same reply, make only transient failures resumable under an explicitly versioned run policy, as detailed in optional architecture item 1 below. Do not change old silence Events, remove no-fallback assertions, auto-retry indefinitely or classify missing canon as transient. **Risk:** pending turns need a bounded abort/skip escape, fresh-head checks and controller replacement handling.

## What the architecture already gets right

`backend/internal/storage/rp_decision_commit.go:32–66` owns commit, checks actor/turn, proposal and fresh input hashes, and rejects stale head. `backend/internal/storage/rp_turn_activation.go:29–59` pins a complete listener accounting plan for restart, respecting external control at lines 124–131. `backend/internal/storage/rp_decision.go:172–184` reads only self/heard accepted dialogue. `backend/internal/storage/rp_private_decision.go:11–29` restricts memory to the actor's own applied, atomically committed decisions and verifies the stored proposal hash at lines 41–47. These are foundations to extend, not reasons to build a second agent-state authority.

`backend/internal/narrative/prose.go:69–80` gives the narrator only committed effects and published style cues, preserves speech through server-expanded quote slots, and forbids player agency fabrication. `backend/internal/narrative/fact_guard.go:20–29` explicitly identifies its natural-language check as a bounded safety net. Canon must continue to outrank model/book prior; attributed speech must continue to be evidence of speaking rather than proof of its claims. A proposed “tea” action cannot become an object or fulfilled promise through prose.

The runtime also already has economic/life goals, opportunity owners, activity outcomes, conversation focus and lexical retrieval. It is inaccurate to say it has no goals, no memory, no initiative or no typed actions. The gaps below concern their integration into sustained conversational intent and available NPC choices.

## Why many repairs have not delivered sustained RP

The recent work mostly repairs valid interfaces: output shape, IDs, visibility, quote handling, missing content and provider parameters. Each can prevent a real failure, but passing a legality contract does not select interesting intentions, keep a topic alive, resolve a promise, or create scene progression. The tested inputs and runtimes also changed across artifacts, leaving limited controlled evidence of experience improvement.

Decision context currently contains the latest 16 self/heard utterances (`backend/internal/storage/rp_decision.go:174–208`), at most three applied private sketches (`rp_private_decision.go:29`), and four lexically relevant older groups from 512 candidates under 6000 runes (`rp_relevant_dialogue.go:15–17,64–66,126–149`). The shared 64 KiB selector can omit even those sketches (`backend/internal/core/rp_context_selection.go:35–79`). None of these bounds is itself wrong; they control privacy/cost. The structural problem is that recency and lexical overlap are the available selection criteria, while continuing an unfinished intention is not a first-class retrieval requirement. A paraphrased “what about that?” after intervening dialogue may have no lexical match; intentions beyond three own decisions disappear. **Inference:** this makes continuity fragile; the four-turn public evidence does not demonstrate that exact failure yet.

The current proposal is one action plus optional expression: speech, movement destination or activity code, and private intent/emotion/stance (`backend/internal/core/rp_decision.go:188–211`). Activities and source history already have terminal status (`rp_decision.go:170–185`; `backend/internal/storage/rp_own_action_source.go:48–83`), but private intent does not. `rp_decision.go:349–381` exposes leave/declared act choices, while the proposal has no general typed object target/action branch. Thus existing object owners cannot simply be exercised by a speech promise. “Sit here” remains an invitation, not submitted player movement; “I'll bring tea” remains speech, not fulfilled action. This is desirable authority separation, but it leaves a thin scene unless the NPC can choose a supported consequential action through that same boundary.

The narrator then has an intentionally narrow job. `backend/internal/narrative/prose.go:269–272` caps sparse input to concise; `fact_guard.go:25–36` forbids unsourced gaze and supports six expression forms. Removing these boundaries would make richer fiction by breaking the requested world model. Adding more prose effort or rewriting accepted speech hides upstream quality and adds latency. It does not establish character persistence.

## Optional architecture changes (three upper bounds, not a required roadmap)

Only item 1 addresses a demonstrated recovery limitation. Items 2 and 3 are conditional designs for a future reproducible scene failure, not endorsed work merely because bounded intent history or action variants exist. Accuracy repairs and delivery verification above take precedence.

### 1. Keep transient provider failure as recoverable orchestration state

**Trigger:** an NPC's transport/deadline fails after player speech and possibly earlier NPC effects are already committed.

**Evidence / impact:** `backend/internal/storage/rp_decision.go:489–508` converts provider error into a silence proposal; `rp_turn.go:143–182` executes actors sequentially and commits that proposal. `rp_decision_commit.go:41,65–66` explicitly accepts provider fallback silence. Once that decision exists, `rp_turn.go:148–153` skips it on resume. Therefore restart prevents duplicates, but it cannot obtain that failed reply for the original settled NPC/turn. The public long-run failure cited above is a concrete occurrence, not just speculation. A provider outage becomes an in-world beat, albeit diagnosed in receipts.

**Smallest design:** add an opt-in recoverable turn policy to the existing run/activation machinery: timeout/transport-unavailable leaves the affected activation pending and returns a bounded public “response interrupted” request state; retry resumes that same turn and skips committed actors. Do not store a world silence for that policy. Keep actual model-chosen silence valid. Missing authored context remains a configuration failure category, not an endlessly retryable outage. A permanently failing activation needs an explicit terminal skip/abort policy; it must not block sessions indefinitely. This is not a background agent or new ledger. Keep bounded attempts per invocation and record total attempts across resumes.

**Compatibility/privacy/recovery risks:** preserve legacy fallback policy for callers/tests that require it until migration is explicit. Do not reinterpret or delete historical fallback Events. Freeze the requested policy with the request hash. Fresh commit must still reject stale heads; resume may rebuild the authorized input after already committed actors, and external controller replacement must still win. Public status must expose interruption, never private draft/error body, endpoint or credentials. Exactly-once keys and partial-turn recovery remain essential.

**Acceptance evidence to collect later:** deterministic injected timeout after one actor commits, process restart, resume without duplicate player/actor effects, fresh-head rejection, controlled-owner takeover, bounded terminal escape and continued next turn. Keep the original strict 32 assertions intact; a new recovery test is additional evidence, not a way to rename fallback as success.

### 2. Give an actor's continuing intention explicit identity and retirement

**Trigger:** a private intention or an accepted promise matters after more than three own decisions, a topic switch, restart, or paraphrased reference.

**Evidence / impact:** `rp_private_decision.go:14–29` retains three sketches; `core/rp_decision.go:207–211` has no intention ID/status. Lexical retrieval only includes groups with positive overlap (`rp_relevant_dialogue.go:126–127`). **Observed:** these mechanisms are bounded history. **Inference:** they cannot reliably distinguish a still-current intention from a superseded or already satisfied one. Existing life goals/activity statuses must remain authoritative; this recommendation does not replace them.

**Smallest design:** extend restricted applied-decision metadata with a bounded optional continuation ID and revision operation (continue, replace, abandon), linked to an actor-owned earlier applied record. Derive a small active set deterministically from those immutable revisions at the branch head, and expose it through the existing `BuildRPDecisionInput` and shared selector, ahead of incidental older dialogue. Retain exact supporting utterance/decision IDs. Start with one active conversational intention per actor/interlocutor and exact associated dialogue; do not introduce embeddings, generated biographies or automatic summaries. A private revision records the actor's approved intention, never objective relationship/scene truth. Where an intention corresponds to an existing activity/task, consume its owner-provided terminal outcome instead of letting the model declare that action fulfilled. If fulfillment cannot be established, expose it as unresolved/actor-reported rather than manufacture completion.

**Compatibility/privacy/recovery risks:** old decisions with no revision remain historical sketches, not automatically active intentions. A creator's later canon amendment must invalidate conflicting derived state. Verify actor, branch, committed batch and proposal hash just as the current memory reader does; referenced supports must be in the authorized input. No private continuation record goes to the narrator, player context, observatory or public Event payload. Bound storage scans/output and deterministic replay. Model-emotion text must never become a durable relationship fact. Give stale/unknown links a fail-closed diagnostic rather than resurrect another actor's intent.

**Acceptance evidence to collect later:** an authored two-character scenario with one intention, more than three intervening own decisions, a paraphrased return, explicit abandonment and activity completion, restart/rebuild and a second observer who never heard the promise. Inspect source IDs and active-set retirement; human review assesses voice and relevance. These would test the missing behavior instead of only testing larger history windows.

### 3. Expose one consequential NPC affordance through existing typed owners

**Trigger:** a character has reason to do something concrete but currently can only talk about it, choose a simple expression, move or start a generic declared activity.

**Evidence / impact:** `core/rp_decision.go:188–204` lacks an object-action/target branch; `storage/rp_decision.go:349–381` adds only destination/activity options in that portion of the builder. `rp_own_action_source.go:78–83` already understands actual object-interaction evidence. Existing object state therefore has a reliable history path, but a broad model-written scene paragraph would bypass it. **Inference:** the narrow decision affordance limits natural scene development; the public short samples show reassurance and repeated expressions, not a consequential object-action failure.

**Smallest design:** choose one supported object interaction required by a fixed authored scene. Build a small authorized list of current legal choices from the existing object/reach/stock owners into the same NPC packet; add exactly one typed observable proposal variant using a listed action/target reference. Route it through that existing owner with fresh permission/reach/stock checks and a single parent decision atomic batch. Start with action only, or whatever effect combination the owner can safely make atomic; do not add arbitrary multi-step scripts. The post-commit witness projection supplies narrative facts in the usual way. Reuse existing activity/task lifecycle where the action takes time. Publish authored public setting/style cues only when independently authorized; private intent is never a setting cue.

**Compatibility/privacy/recovery risks:** speech inviting player action must never perform the player's action or imply consent. Unknown/unreachable/hidden objects must not appear in the list. Concurrent stock consumption, ownership/controller changes and stale branch heads must fail at commit; retries must not consume twice. Legacy decision variants remain valid. Do not claim this solves every interaction or expand to a universal planner. Do not relax the sparse-evidence cap or exact-speech rule: richer narration should follow more actual witnessed events, not precede them.

**Acceptance evidence to collect later:** one authorized NPC action changes the existing object projection and yields a witnessed public fact; another observer cannot see it; no-stock and out-of-reach fail; restart/replay consumes once; a spoken promise alone changes nothing. Review the same facts with concise and standard prose to judge whether the added scene consequence helps, separately from legality.

1. **Prerequisite, not another architecture change:** get explicit creator approval for one small real character/relationship/scene version through the existing authored-event path. Keep the frozen missing-data world unchanged as a negative fixture. The current unapproved two-person fixture is useful diagnostic data, not consent or canon. Readiness already exists; use it rather than rebuilding it.
2. Bind the inspected authored version to the actually running preview version before making a product improvement claim. Prepare this read-only release comparison first; deployment requires separate authority. Retain the old preview result and frozen missing-data evidence.
3. Review the unsupported-premise sample on fixed authored input and repair the decision instruction or narrow the claimed semantic guarantee. Inspect actual provider packets privately, not just canonical builder output. Demonstrate any field loss/masking or semantic regression before implementing a structural change.
4. Verify provider interruption with injected failures and existing recovery/receipt paths. Only if same-turn reply recovery is required, implement optional architecture item 1. This cannot ensure a stochastic provider passes the original strict no-fallback long run.
5. Stress continuity and actual action using small authored scenarios. If a sourced intention is demonstrably lost beyond the current bounds, consider item 2; if a required already-supported owner action cannot be proposed by an NPC, consider item 3. 6. After the demonstrated repairs pass, run the unchanged original 32 and postchecks plus comparable authored Golden and human rubric. Separate legality, model completion, semantic quality and release identity. Current checked-in evidence does not provide a full original long-run or human experience pass.

No change is recommended to typed world authority, private/observable separation, exact accepted speech, canon precedence, external controller ownership or historical ledger records. This audit recommends a bounded continuation of those foundations, not a second prompt pipeline or a narrator that invents the missing world.

## Independent review of in-progress accuracy increment

Reviewed the working diff after the parent requested a second review. This section refers to working-tree line numbers, not the original HEAD-only audit. Workers were still updating fixtures/metadata; no tests or provider calls were run by this reviewer. Findings below derive from executable branches, not old-format test failures. ### P1 — Composition removes the established free-prose capability while keeping its name

**Concrete change:** `backend/internal/narrative/prose.go:272–303` now exclusively requests/accepts composition; `composition.go:63–67` forbids all connective sentences and labels. At lines 178–186 each fact is rendered separately through a deterministic provider after forcibly setting concise density, zero description, normal verbosity, plain pack and no public presentation. The model's choices are only grouping, newlines and plain/dialogue. `prose.go:66` still returns `full_prose` and storage retains that provider mode.

**Trigger/impact:** a user chooses long/standard prose, expressive published character style, custom prose instructions or scene-supported rich narration. Those settings now reach the provider, but cannot affect lexical phrasing at all; the template protocol rejects the previously supported actual prose. Same-event speaker-swap is closed, but this is a product capability reduction, not simply a corrected prose validator. Authored public style is effectively reduced to layout preference. This conclusion is direct source evidence; user-quality consequences need review.

**Minimal correction:** do not silently replace the existing named capability. Make this an explicitly named/versioned safe composition mode and report its unsupported prose/style requirements, or preserve the required expressiveness with a finite set of server-owned connective/expression templates attached to immutable fact atoms. Expand only presentation choices; no model actor names, speech text, actions, hidden thoughts or world authority. At minimum support more than two templates and retain valid sourced place/time/style presentation instead of discarding it unconditionally. Parent should decide whether the reduced capability meets the user's request before treating fixed-atom fixture migrations as acceptance. Raw legacy saved prose remains readable; this concern is about newly requested behavior, not loading old rows.

### P2 — Dialogue template loses the committed refusal stance

**Source:** `compositionSpeech` (`composition.go:234–235`) treats speak/respond/refuse identically, while `renderComposition:192–206` produces only actor label plus original words for all three. The deterministic plain path distinguishes refuse with “拒绝了” (`core/rp_style.go:303–309`).

**Trigger:** a `refuse` fact with speech that does not independently make the refusal obvious; the model selects allowed `dialogue`. Its Event ID is included, but the public rendering omits the action distinction. Strict reference coverage therefore is not full semantic fact coverage.

**Minimal correction:** either disallow the generic dialogue template for refusal or give it an immutable server-owned refusal marker. Add one non-obvious refusal case comparing plain/dialogue, rather than only asserting all IDs appear. If dropping stance is an intentional product rule, document that reduced guarantee rather than saying every supplied action survives. No actor/target swapping was demonstrated in the plain path; expression target handling reuses the existing deterministic renderer.

### P2 — Several reload paths validate receipt groups against themselves

**Source:** `storage/rp_narrative_render.go:61–70` flattens `groups` into `ids`, then passes those very IDs as the expected `EventIDs`. This accepts `[["unknown"]]`, or `[["same","same"]]`, for an appropriately sized versioned line set: equality is tautological, and uniqueness is not checked. `SelectRPNarrative` at lines 208–212, `rp_session.go:540–562`, and `rp_turn.go:547–555` rely on this decoder alone. By contrast `savedRPOfficialNarrative` (`rp_style.go:456–467`) subsequently validates against independently rebuilt input facts.

**Trigger/impact:** corrupted/mismatched persisted groups, including duplicate or nonexistent sources, survive selected history/turn result reload and claim the strong composition version. Current saveSelected validation checks independently supplied input order before saving (`rp_narrative_render.go:83–91`), so this is a recovery integrity gap, not evidence that ordinary model output can forge rows or cross privacy boundaries. It is independent of test fixture migration.

**Minimal correction:** let the decoder accept an independent expected fact sequence and compare/uniqueness-check it on reload. For render rows, do not confuse authored public-style provenance with facts: compare the ordered fact groups to a reconstructed authorized input or independently stored fact-only sequence. Reuse the existing saved-official validation path where possible. A restart test should perturb only groups (unknown/duplicate/reordered source) while leaving lines and independent provenance fixed and require ProjectionDiverged. Legacy unversioned rows must remain unversioned/readable.

### P2 — Missing recent-exchange members still depend on lexical admission

**Source:** `storage/rp_relevant_dialogue.go:127` now allows a complete candidate group with missing members; nevertheless lines 130–140 require positive lexical score, and lines 133–134 suppress a term occurring in more than half of at least four groups. No explicit priority/admission exists for an exchange partly retained in recent dialogue. Thus a recent reply's missing qualifying question remains excluded if the current question is a paraphrase with no match, or its only matching term is common. This is direct static counterexample reasoning, not a runtime reproduction.

**Minimal correction:** distinguish “has recent member and missing authorized sibling” from general older groups. Restore the former ahead of lexical retrieval under the existing group/rune/byte budget, or narrow architecture.md's promise to lexical candidates only and expose omission. Do not raise bounds or grant unheard siblings. The SQL window count correctly applies after hearing/head filters and rejects candidate-window-cut groups; that rejection intentionally avoids falsely claiming a full exchange, but no explicit completeness/omission field is returned. If the contract requires distinguishing bounded partial views, add bounded selection diagnostics rather than a summary or new memory store. The final shared selector also prioritizes recent utterances individually and relevant groups separately; verify that it cannot once again omit the restored group at budget pressure before claiming an end-to-end recovery guarantee.

### Provider typed masking: no demonstrated current defect, but current test coverage is incomplete

`storage/rp_decision_provider_view.go:16–39` correctly puts head, internal owner check, familiarity and alias-secret reads in a short transaction; lines 92–113 finish projection/budgeting after releasing it. That is consistent with the intended no-transaction-over-provider rule. The inspected reachable decision structures' person-reference fields are covered by the key allowlist at lines 119–128; IDs in provenance, excerpt and subjective text now stay exact. I found no concrete missing person field in those inspected structures and no demonstrated snapshot leak. Organization/institution/place IDs are separate non-person references; adding them indiscriminately to the unfamiliar-person list would be wrong.

`rp_decision_provider_view_test.go:97–119` tests manually copied key lists against manually built maps. It proves exact matching, but will not catch a new reachable person-reference field omitted from both lists. A focused reflection/schema inventory over RPDecisionInput's actual nested fields would make this coverage claim reviewable; include observer-relative handles as intentional exclusions. This is a verification gap, not a current leak finding. External owner enforcement at the provider boundary is appropriate; final commit must continue to reject changes after snapshot release.
