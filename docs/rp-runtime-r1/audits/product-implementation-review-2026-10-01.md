## Immediate priorities

### P2 — Explicit actor binding weakens in combined subject-first gesture output

`backend/internal/core/rp_composition.go:292–293` renders `name + speech + newline + gesture`, omitting the actor on the new gesture line. The immutable plan ties it internally to a companion, but the player sees an unlabeled action. If accepted speech mentions or quotes another person, the nearest named actor inside the quote can compete with the actual gesture actor. Example sourced speech from A mentioning B followed by an unlabelled “向你招手。” is harder to attribute than the internally correct source group suggests. This is a public clarity/attribution risk, not a demonstrated event reassignment.

Minimal correction: retain the bound actor on the second sentence/line, or keep the entire combined beat in one unambiguous sentence with an explicit subject and ordered connective. Do not infer pronoun gender. Include speech that names another actor in a combined-beat check. Source order must remain speech then expression; shared time/batch is not concurrency evidence. Quote-first “A答道，招手” should not be interpreted as authorization to render “一边说一边招手”.

### P2 — One public character cue applies a global register to the entire turn

`rp_composition.go:125–129` sets plan.Register to classical when any public cue contains “从容/古典/长辈”. `rpSpeechVerb:246–262` then applies that register to all speech atoms, including the controlled player and other NPCs. In a multi-character scene, one elder cue can change everyone to “道/答道/应道”; a calm modern speaker's cue containing “从容” can also trigger classical wording. This changes no facts, but weakens the promised character-specific presentation and can homogenize the cast.

Minimal correction: reserve global register for explicitly requested world/user style; choose actor-scoped eligible diction from that actor's published cue for each beat. Treat a literal “从容” as demeanor/author cue, not automatically ancient setting. If the deliberate product choice is world-wide classical narration, define it in the authored world style rather than derive it from an arbitrary single actor. Tests should contrast two actors with different cues and a calm modern cue.

### P3 — Alternating forms by fact index is varied output, not contextual rhythm

`rp_composition.go:140–147` alternates lexical and quote-first choices by index parity. This is stable and source-safe, but it is unrelated to dialogue function or scene importance; unrelated facts added before a beat can change its wording. It may yield noticeably repetitive cadence over many turns. Minimal improvement inside this renderer: make supported form choices depend on actual beat structure and requested density, using a stable frozen source key only for equally valid lexical alternatives. This is a product critique requiring transcript review, not a hard integrity failure. Do not add a semantic fun gate.

### P1 — Recomputed artifact hash does not validate all public fields

`validateRPNarrativeArtifactOnConn:158–171` checks an ordinary Input hash, annotates/verifies facts, then requires regenerated lines/IDs/groups to match the stored view. If a public field is changed and the hash and finite-expanded view are changed consistently, only `validateRPNarrativeFact` can reject it. Its current branches leave gaps:

- **PlaceName:** no action branch compares it with a source place ID/name. Speech validation at lines 62–74 checks words/actor/hearing but not location; expression at 76–93 checks code/witness/target but not place. A forged sourced scene prefix can therefore pass with the correct speech/action Event ID.
- **ActivityLabel / ActivityLabels:** activity branches at 101–103 only compare the activity code; the narrator's fallback realization uses a supplied label directly. Changing it to a fabricated action phrase and recomputing output/hash is not rejected. The package-derived map is likewise unverified. These values are presentation text but become public factual wording.
- **PublicPresentations:** no validator checks actor/name/text/source provenance against the committed published declaration. `rp_narrative_presentation.go:22–59` already defines the authorized reader and explicitly excludes private persona inference. The artifact needs the same source-specific check at its historical head, not merely any valid cue string and ID. Current finite output may use only a cue's register keywords, but persisting an arbitrary cue as authorized public input undermines the privacy/data boundary and future optional-provider use.
- **Unused typed fields:** speech/expression branches return early without checking that object/activity/target/text fields irrelevant to that action are absent or equal to the canonical projection. Present rendering may ignore many of them, but an internal artifact represented as frozen authorized public input must not carry invented or private data. Narrow action-specific equality is safer than silently accepting ignored fields.

Minimal repair: reconstruct each fact's complete allowed public field set from its immutable committed source plus source-specific frozen observation and historical declaration/package evidence; compare every applicable field and reject incompatible extras. Bind historical place/display/label/cue provenance explicitly. A cryptographic hash checks consistent storage, not independent authority. Do not repair by sanitizing away corrupt fields after accepting the strong version.

### P1 — Movement action kind is interchangeable in the draft

Preserve legitimate historical interpretations and do not use today's position to choose the old role.

### Why inaccuracy remains despite the kernel work

The kernel protects who may commit an action, which facts an observer may see, and which committed sources a renderer may use. A speech fact authorizes attribution of the accepted words to that character; it does not establish every proposition inside those words. A receipt or basis reference similarly cannot entail “I mentioned you earlier,” “you grew up before my eyes,” “your hands are always cold,” or “the night is chilly.” Here the renderer faithfully quotes inaccurate speech, and later dialogue repeats some of the model's own inventions. Stronger persistence can preserve the error consistently; it does not turn it into author canon.

The concrete remaining accuracy work is therefore in decision context and acceptance: distinguish declared facts from invitations, conditional offers, remembered utterances and unsupported propositions; ensure remembered dialogue does not independently authorize its asserted world history; and validate the resulting speech against the supplied sources with focused qualitative cases. This review does not propose rejecting every metaphor, promise, character opinion or speculative question. Those differ from unsupported factual assertions and should remain playable. The paired capture establishes both a presentation gain and continuing semantic defects; it does not justify “accuracy solved,” “more enjoyable,” or human PASS. Original sustained/R1 acceptance and release evidence remain separate requirements.
