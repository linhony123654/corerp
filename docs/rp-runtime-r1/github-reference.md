# Open-source RP references inspected for R1

- [SillyTavern World Info documentation](https://github.com/SillyTavern/SillyTavern-Docs/blob/main/Usage/worldinfo.md) and [implementation](https://github.com/SillyTavern/SillyTavern/blob/release/public/scripts/world-info.js): world knowledge is activated from recent chat and scoped to character/persona/chat; selection respects depth and budget. Useful for **bounded relevant-memory selection** rather than sending the entire history. Its entries are prompt material, not CoreRP-style authoritative world events.
- [SillyTavern default prompt preset](https://github.com/SillyTavern/SillyTavern/blob/release/default/content/presets/openai/Default.json): character description, personality, scenario, persona, world info, examples and chat history are distinct prompt slots. Useful evidence that role identity needs distinct stable inputs, but R1 should encode these as sourced fields in its one context contract, not expose independent user-editable prompt chains.
- [RisuAI lorebook implementation](https://github.com/kwaroran/RisuAI/blob/main/src/ts/process/lorebook.svelte.ts): activated lore entries are sorted by priority, fitted under a token budget, then sorted for insertion order; entries retain a source label. Useful for relevant-memory budget and diagnostics. R1 must additionally filter by NPC observation/permission *before* ranking and never treat triggered lore as newly committed fact.
- [Agnai Memory Books documentation](https://github.com/agnaistic/agnai/blob/dev/instructions/memory.md): keyword matching scans bounded recent messages, with priority and weight controlling budget and placement. This supports an explicit context-budget policy; browser-side chat history limits are unsuitable as CoreRP's authority source.

Design decision: borrow **selection, scoping and budget transparency**. Do not borrow prompt injection as a substitute for authored canon, typed observable commits or replayable knowledge. No external project reviewed here demonstrates CoreRP's required private/observable boundary, so that boundary remains a local contract and test obligation.

## Current input-presentation reference (2026-10-01)

Rechecked the primary [SillyTavern prompt-manager documentation](https://docs.sillytavern.app/usage/prompts/prompt-manager/) and [release default preset](https://github.com/SillyTavern/SillyTavern/blob/release/default/content/presets/openai/Default.json). Character description/personality, scenario and chat history are separate placements, with explicit ordering and boundaries before history. The default preset also disables Enhance Definitions. This supports a presentation hypothesis, not a claim that their scheme proves facts or will improve CoreRP: serialize the one selected authorized NPC input into distinct canon, snapshot, utterance, action-history, private-history and plan sections. Do not copy optional model-added lore or create a second prompt/world source. Comparable actual Step output remains the evidence needed to assess the hypothesis.
