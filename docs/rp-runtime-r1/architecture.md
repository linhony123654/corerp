# RP Runtime R1 architecture contract

## Authority and scope

The existing event ledger, typed owner and projections remain the only world authority. A proposal cannot create facts; the NPC decision commit rereads the branch head and input hash. The narrator reads committed/public evidence after settlement. No model output is allowed to amend character canon.

This is an evolution of `BuildRPDecisionInput`, not a second prompt pipeline. It continues to build the authorized NPC view. The existing `readRPNarrativeInput` remains the post-commit public projection, with the same provenance vocabulary but never a copy of NPC-private decision fields. The `decisionContext` encoder is a serialization adapter, not another source of world state.

## Context contract

`RPDecisionInput` gains a version, explicit readiness and sourced character relationship/address entries. Existing fields already provide branch head/world time, own persona, visible actors, witnessed dialogue, bounded older player speech, knowledge, life, goals, activity, legal actions and trigger. New data must point at a committed event (`StudioWorldPrepared`, `RPIdentitiesDeclared` or later authored amendment), or be marked `unknown`/`missing`. Player utterance claims remain attributed speech, not objective truth.

An authored directional relationship consists of actor, subject, role, address-to-subject and optional self-reference. The declaration does not infer a reciprocal role, a family tree, or facts from names. A declared relationship entails recognition and is made familiar through the existing identity projection; an undeclared pair remains unknown. `persona_text=''` yields readiness `persona=MISSING`, not a generated biography. Relationship/address can be `UNKNOWN` when no declaration exists; `MISSING` is reserved for a declaration that is incomplete. Existing worlds remain valid and readable.

The provider view retains observer-scoped identity masking. Relationship entries must be removed or masked when their subject is unfamiliar; no new field may reveal private IDs or third-party state. `StudioWorldPerson.public_presentation` is an optional, explicitly authored narrator cue distinct from private `persona`. Its declaration source is `StudioWorldPrepared`; it enters narration only for an identified actor with a current public fact. Existing worlds with no declaration receive no inferred style. The narrator never gets the NPC's complete packet, own account, private goals, or unobserved knowledge.

The Studio creation form now collects this existing declaration instead of submitting names alone. New UI drafts require an NPC persona; directional roles and address forms are separately entered only when the creator explicitly declares familiarity. Player background and narrator-facing public style are optional and remain separate. Successful creation returns creator-only `rp_readiness` derived from the validated, frozen request. It reports `READY`/`INCOMPLETE`, NPC readiness and declared relationships missing address forms, with no private persona text. An unknown relationship is valid, not an inferred relationship. This is configuration completeness, not live-world or experience readiness; legacy API requests remain compatible and recovery reuses the same authored request. The existing Studio owner commits all declarations before the receipt; no migration, new owner or competing world state was added. See [creation verification](role-create-2026-09-30.md).

## Decision and consistency contract

NPC wire v3 now serializes a closed `private` object and exactly one typed `observable` branch; speech, stance, movement and declared activity have different required fields. The schema derives choices from the same authorized `RPDecisionInput`. The adapter locally rejects mixed roots, duplicate/null/extra fields and incompatible effect combinations; the existing core and owners still validate grounding, head, permissions and commit. Strict legacy responses remain readable without silently discarding effects. No new packet, state, owner or world-writing LLM layer was added. Actual Step protocol probes and source-specific verification are in [the wire v3 record](decision-wire-v3-2026-09-30.md).

The player history projection groups a witnessed NPC expression into its own observer's already-settled parent turn when atomic batch, causation, actor and decision lineage match. During unfinished-turn recovery, or for another observer, the standalone witnessed receipt remains available. This changes presentation grouping, not facts, observation scope, or regeneration authority.

2026-09-30 context follow-up: the existing builder now also selects bounded `relevant_dialogue` from accepted self/heard speech at the current branch head. Exact attributed utterances are grouped by their source parent turn, ranked deterministically by lexical overlap with the player's current words, and kept outside the recent window with a 4-group/6000-rune output bound from at most 512 candidates. Each utterance retains its Event ID and independently satisfies hearing visibility; a selected group never authorizes unseen siblings. No summaries, new projections or canonical claims are created. The selector is not semantic memory and does not imply promises were fulfilled. Current limitations and the broader runtime audit are in [the architecture review](runtime-architecture-review-2026-09-30.md).

The model may propose private intent, bounded emotional/relationship stance, and source references alongside the existing action fields. The private part is decision metadata, not an Event or a fact shown to the player. The same builder also reads at most three of this actor's earlier applied private sketches from the existing immutable `rp_npc_decisions` source. Each joins the actual actor-owned Event, committed command/attempt and complete atomic batch at the current branch head; the stored proposal hash is rechecked. Audit-only, rolled-back, current-turn or other-actor proposals do not enter memory. It retains the original interlocutor, time, sequence and source IDs, is deterministic across rebuild/restart, and creates no private projection or second world state. This is historical motivation continuity, not an unfinished-goal lifecycle: it does not mark a goal current, fulfilled or cancelled. Current canon/readiness/observable state always take precedence. The narrator, public observation and observatory receive none of it. A model-supplied rationale is not chain-of-thought authority. Grounding references may only cite IDs present in the authorized input. Missing/invalid refs are hard invalid proposals. Semantics such as reply relevance, voice, repetition or suspected self-introduction without a reliable marker are warnings/repair hints, not unconditional commit blockers.

The observable proposal remains typed: speech, movement, declared activity, silence/wait, plus a small supported visual expression vocabulary. An NPC may also answer without words: `silence` or `wait` plus a supported expression. The existing decision owner commits the decision and expression atomically under the same validated branch snapshot; the visual event uses the existing nonverbal claim/witness projection and replay rules. No free-form gesture text becomes world authority. One NPC decision remains one idempotent turn decision even if its event batch contains two effects.

Spoken and elapsed-time initiative owners now share the same expression preparation/commit functions. A valid initiative expression is a second `RPNonverbalAction` in the existing atomic batch, with a parent decision causation ID and the source wait ID; it is included in branch/clock settlement and retry/replay. Cadence and roster selection count the main decision once, not every effect. Initiative Event payloads omit `proposal.private`; the full approved proposal remains only in restricted immutable decision/audit records. Existing historical Events are not rewritten. A later narrative window can include a supported NPC expression only from this player's frozen witness record at the relevant place; targeted expressions must have a visible target equal to the controlled player. Third-party target effects and the wider player nonverbal vocabulary are not silently reduced to untargeted NPC expressions. Becoming able to see the actor later cannot grant knowledge of an earlier unwitnessed expression.

Hard checks: legal action/fields and owner; branch head/input hash; grounding ref membership; declared relationship/identity conflict where deterministically provable; expression vocabulary/visibility; private fields excluded from public projections; prose exact utterances and common uncommitted observable patterns. Soft signals: repetitive wording, relevance, persona drift, expressive quality and multi-person turn-taking. A named addressee may decline, and another NPC may have a justified reason to speak; the 32-turn harness records addressed replies and other speakers for review without treating a semantic turn-taking judgment as a world-integrity failure. Repetition is diagnostic only and never requests a synchronous rewrite or rejects an otherwise legal proposal. A hard check's failure must not silently become an apparent accepted RP beat.

The existing orchestrated/multi-agent activation plan accepts familiar canonical names and the controlled player's own sourced directional `address_to` forms. It does not infer addressing vocabulary from reverse relationships or private NPC persona. The responder limit, external controller ownership, pinned plan and restart behavior stay authoritative. Undirected fallback still uses stable ordering; natural turn-taking remains an experience signal rather than a semantic hard gate. The decision schema now enumerates only Event IDs actually present in the authorized context and declares the same 2000-rune speech bound as local validation; neither constraint replaces validation at commit.

The chat adapter keeps a default 1024-token NPC decision completion budget; operators can set `CORERP_LLM_DECISION_MAX_TOKENS` from 512 to 8192 for models that need more output tokens before producing the schema. Decision timeouts are bounded at two minutes. A response explicitly ended by `finish_reason=length` may be retried once at no more than twice the configured budget (capped at 8192). An unauthorized private `basis_event_ids` reference or incompatible action/field combination may trigger one fresh proposal with fixed contract feedback; both share one invalid-proposal repair budget. The rejected first proposal is never committed, and the second is validated from scratch. Other malformed or unlawful outputs remain failures. The provider receipt counts actual HTTP attempts and exposes only bounded diagnostic categories.

Formatting residue alone may request the existing single soft-quality rewrite; semantic repetition remains diagnostic only. The narrow formatting signal checks excess ASCII closing structure after a finished spoken sentence, preserving balanced literal code and player-requested punctuation. It neither trims approved speech nor makes a semantic hint a hard gate; a second legal proposal remains admissible. Length/invalid-proposal repair keeps its existing bounds. Real token-field probes found both relay aliases enforcing a 64-token cap; no provider-name special case or field substitution was introduced. See [the compatibility evidence](step-token-parameter-probe-2026-09-30.json).

## Narration boundary

`RPNarrativeInput` contains committed/public facts and the separate sourced public-presentation cues only. Accepted NPC speech requires a frozen `speaker_said` observation for the controlled player, both in the current turn and in the cross-turn window; sharing a place or session alone is insufficient. An accepted NPC visual expression enters it by Event ID and requires a witnessed observation. For activity and movement, the narrator reconstructs the player's visual access at the source event sequence from committed movement, zone-choice and perception-link events. This history view does not use today's position to reinterpret an older turn and does not add an RP world state. The returned narrative view keeps one `EventID` per committed fact; a saved render additionally records the source ID of any authored public style context. Style context is never counted as an observable turn fact. Narrator instructions can choose rhythm, focus, syntax, connective tissue, and scene atmosphere supported by published information. A public style cue may affect wording but cannot authorize a new action, mental state, fact or utterance. When a turn has at most two public speech facts and no other observable or authored public style cue, the effective prose density is capped at dialogue-led `concise` even if the broader style requests long prose; this prevents unsupported padding without changing the saved style preference or any world fact. Longer prose remains available when the public evidence supports it. The narrator cannot invent an interactable action, object, character, change of location, private intent, knowledge, or rewrite an accepted utterance. The fact guard rejects explicit unsourced gaze toward the controlled player. For expressions, it recognizes a leading actor and can carry that actor across a comma within one sentence, while treating names after `对/向/给` as recipients and rejecting ambiguous or competing subjects; it resets attribution at sentence boundaries. This remains a bounded safety net; no regex is described as a complete semantic proof.

Step 5 Preview exposed a second sparse-evidence case: one player utterance plus committed NPC silence. This now receives the same concise density cap and a length ceiling derived from the exact public utterance, since silence cannot license several paragraphs of invented scene beats. Explicit uncommitted player gaze and intent are rejected even if the draft quotes accepted speech verbatim. The recorded violating Step draft is a regression test; it cannot become public prose and instead takes the sourced deterministic fallback.

Quoted speech and narrative claims now use the same delimiter-stack parser for nested `「」` and `“”`. Exact committed speech can contain an inner quote of the same style; the entire outer span is checked and removed from claim detection. The original first-close scanner misclassified such speech as invented dialogue and could leave its suffix in narrative action checks. Mismatched or unclosed delimiters remain invalid, and extra quotations or actions outside the accepted speech remain unauthorized. The sourced nested-quote fixture and positive/negative tests demonstrate the boundary, without treating an attributed NPC claim as true world state.

The prose adapter supplies a local `quote_token` for each public fact with immutable speech. The model composes the surrounding prose and references these slots; the renderer inserts the exact source speech plus quotation marks in one pass. Missing, repeated, unknown or malformed references are invalid. References inside newly inserted source speech are never executed recursively, and a literal reference in already-valid legacy quoted speech stays data. Legacy direct quotes remain subject to the same strict validation. The expanded text then passes the existing exact-speech, visibility, agency and observable guard before streaming or persistence. There is one authorized narrative input and one provider chain; these slots are presentation references, not new world facts or a second Context builder. This protects even unattractive source text from silent correction by the narrator. NPC output quality remains an experience issue rather than being hidden by rendering. Optional `CORERP_NARRATIVE_DEBUG` logs a fixed validation category only, never a draft, speech, ID, endpoint or credential.

1. Readiness on the frozen world: the current 贾母 packet reports missing persona and unknown kinship/address, without changing world state.
2. A newly authored isolated fixture carries a sourced directional relationship/address and nonempty persona; NPC context includes them, provider view masks all other unknown people, and commit rejects stale/ungrounded proposals.
3. A response with one supported observable gesture commits speech plus a witnessed, replayable expression; next NPC packet can see that observation. Narrator uses both, while an uncommitted gesture is rejected or omitted.
4. Run focused storage/core/decision/narrative tests, old 32-turn technical suite, then paired frozen Golden with human review.

The baseline world currently lacks character canon. No claim of a passed relationship experience gate is possible until the creator supplies source content and the same authored fixture is tested before and after. The original source-world baseline remains frozen and separate from any later explicitly authored fixture.
