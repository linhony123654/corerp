## 1. Baseline 暴露的结构性问题

冻结荣庆堂的 11 个角色缺少人设、关系、称呼；原著常识不是该世界的 canon。模型据名字表现亲疏，无法证明关系真的由世界设定驱动。宽工程输出和累计的指令还导致空内容、截断、不合约 JSON，再经同步修复拉长等待。此前原 32 轮在 ac0 检查点第 2 轮 timeout、简化指令检查点第 1 轮无效输出失败；不能将它们归为账本损坏。

JSON Mode 加同一 schema 的单次探针成功，却在实际连续对话中反复返回错误根结构。它是失败候选，不能因为一个快探针就推荐给玩家。随后使用单一原生函数提案，原型四轮通过，再接入产品代码并重新进行四轮验证；原型与产品不是同一段八轮对话。

## 2. Context Contract

继续由 `BuildRPDecisionInput` 提供唯一事实入口：来源/head、persona、已声明关系与称呼、可见场景、实际听见的近期和相关旧对白、角色获准知识、本人已应用的私有决策历史及 readiness。确定性选择、身份遮罩和授权源集合保留；没有另一份 RP 世界或模型生成的 canon。

本次只改变模型请求的呈现方式。角色身份及眼前交流优先，工程约束压缩为通用契约；原生函数的 parameters 使用原来的闭合 schema 和授权引用枚举，获准输入保持相同。缺数据继续显式 incomplete，不能承诺荣庆堂已有人物关系。

## 3. NPC Decision Contract

新增显式 `decision_format=tool_call` / `CORERP_LLM_DECISION_FORMAT=tool_call`。默认仍是 `json_schema`，不按模型名称猜格式；网页模型配置可选择。`json_object` 兼容选项保留，但本次 Step 连续对话没有通过该格式。

请求只声明 `propose_rp_decision` 一个函数，返回内容仍必须是 `private + observable`，private 只收短的意图/情绪/关系姿态摘要。它是服务端提案接口，不执行模型工具，也不接受自由文本直接修改世界。普通 assistant content 被忽略；仅一个名称、类型和参数都合法的函数提案进入原解析器。未知/多个函数、重复字段、旧根结构、非法依据、额外效果、截断输出均拒绝。

## 4. Observable / Private Boundary

函数 arguments 不是已发生事实，仍须经过 provider-view 校验、canonical 校验、typed owner 和原子事件提交。private 不进入 Narrator/公开观测；提交失败不得公开 proposal。HTTP 集成测试验证普通模型文字和 private 不会泄漏，幂等重放不会再次调用模型。

当前四轮公开的两次笑、两次点头各有 `RPNonverbalAction` 及一个目击 observation，已逐项核实。对白中的“坐这儿陪你”不证明已经发生坐下动作，不能据此增加位置/姿态事实。

## 5. Narrator

保持公开投影、服务器插入 committed 原话和原事实检查。可以组织节奏、措辞、关注焦点并表达已提交行为；不能补动作、人物、物品、位置变化或 private 信息。本次原生提案没有进一步放宽 Narrator。四轮采用确定性 Narrator，因此它们不证明文学叙事改善；原 32 轮仍使用真实 Full Prose。

## 6. Hard Rule / Soft Signal

结构、授权来源、身份可见性、明确关系/称呼约束、行动合法性、head/owner、事实保真及公开/private 分隔是硬规则。结构修复至多一次，沿用同一输入、schema 和总时间上限；不剥离非法字段来“抢救”提案。

重复、答非所问、人格味和自然度继续是诊断/人工评价。不能因不可靠的语义分类器阻塞正常对白，也不能把机器绿灯解释为有趣。
