# RP-5 organization decision source

Status: bounded rule-based review and opt-in scheduled invocation implemented with actual effects/recovery evidence; not general autonomous organization management or full RP-5 acceptance.

Reuse existing Career organization creator authority, manager authorization, employee leave requests, atomic review, owned schedule cancellation, earned wages, own decision memories and work-change opportunity reactions. No alternate contract/schedule/pay authority.

Optional immutable organization `leave_review_policy.max_concurrent_employees` (1–100) enables manager-authenticated `Decision:"consider"` on the existing leave-review command. Ordinary approve/reject and organizations without a policy retain existing behavior. The rule is an organization-authored limit on simultaneously approved employees, not a universal legal rule or inferred minimum staffing requirement. Explicit managerial overrides remain possible through approve/reject.

Consider requires a valid future leave window. For every requested day, count distinct other employees with current approved overlapping leave in the same organization and branch. Pending/rejected requests and non-overlapping windows do not count. Approve only when adding this employee stays within the declared limit on every day. The transaction pins organization policy Event, relevant approval Events, peak count, decision and reason. Capacity is re-read at commit, so sequential competing requests cannot both consume the last place. A closed request cannot be reconsidered with a fresh key; exact retries retain the original decision, including after later history/restart. There is no random reroll or fixed-turn guarantee.

The requesting employee can learn their own decision through existing memory/read paths, but the managerial assessment (including other people's source IDs) is omitted from employee reads. Actual approved leave cancels only owned future work and preserves existing base-pay rules; rejection changes no schedule. Known work-change reactions can subsequently use the existing own_leave_decision source. No global disclosure, external model or new HTTP route is introduced.

Required evidence: configured/unconfigured and invalid-policy boundaries; actual approval/rejection from sourced overlapping requests; half-open window and distinct employee semantics; authority/privacy; rollback, retry/restart/rebuild; actual attendance/pay and own memory. Until demonstrated, these are acceptance requirements, not verified claims.

Initial actual integration PASS1.521s: unconfigured policy rejects consideration; one-place policy approves Ada and rejects overlapping Bo, two-place policy approves both; next non-overlapping window is approved. Tests check manager authority, injected rollback, policy/prior-approval provenance, employee-read redaction, retry after reopen/rebuild, refusal to reopen a closed request under a fresh key, actual attendance versus approved leave and unchanged base wages. Extended tests also require own decision memories to qualify for the existing work-change source; existing HTTP lifecycle now exercises consideration, authenticated review, redaction and restart. Expanded regression/race terminal results are recorded in project progress. Distinct employees are counted with per-day sets; no dedicated multi-contract same-person fixture or competing-command concurrency test is claimed.

API: include `organization.leave_review_policy:{"max_concurrent_employees":1}` at authorized `/api/v1/career/organizations/define`; send `decision:"consider"` with the existing binding, leave_id and nonempty notice to `/api/v1/career/leave/review`. Omit the policy to retain legacy installation hashes and explicit-only review. Existing organizations cannot be silently redefined to add this policy; amendment/migration remains separate work.

## Opt-in scheduled review

Optional `leave_review_policy.auto_review_delay_minutes` is 0 (default, no automation) or 1–1440. A real employee leave request atomically pins policy Event, original manager principal, due world time and queue identity; the existing world scheduler drains it during ordinary Wait/RunAgentLife progression. No global poller or model call is introduced. If the delay would reach or exceed the first owned shift deadline, the request remains manual-only rather than scheduling a retroactive approval.

At due time, verify exact request/policy/terms provenance, queue identity/time/priority/payload, current manager authority and current reviewability. Reuse the same prepare/decision/cancellation path as explicit review. A closed request, invalidated leave window, conflicting accepted overtime or lost manager permission yields one private `CareerLeaveAutoReviewSkipped` Event and completes the queue, without overwriting the earlier decision or cancelling work. Storage/provenance errors remain errors, never silently counted as a skip. No repeated retry or per-turn guaranteed event: one genuine request yields at most one scheduled attempt.

Scheduled accepted decisions retain the existing private `RPCareerFactRecorded` shape and own-memory source. The scheduler remains system actor; the fact identifies the policy-bound reviewer, not a fabricated human click. Queue comparison/rebuild derives pending/completed state from original request and terminal Event, including skipped attempts; it neither reruns the decision nor regenerates a deadline.

Initial actual automatic/manual-first/revoked cases PASS1.132s: request retry creates one queue, corrupted priority is rejected and detected/repaired, precommit failure rolls back, process reopen and real Wait execute due work, employee reads redact assessment, no public outbox, corrupt completed→pending status repairs without a second decision, and actual attendance/base wage remain correct. Late-request and expanded regression/race evidence is tracked in project progress. Large-organization scale, policy amendment, and other organization decision kinds remain open.
