## F3 shared action-window implementation finding
- Cross-principal rotation design: enrollment is a two-slot current projection, not a lifetime list of all principals. A sourced local-operator replacement after explicit `released` authority changes one Entity's enrolled principal/controller instance without changing the released generation. Assignment then advances from that exact generation. Projected enrollment replay must fold enroll/replacement events in order; authority replay must validate each assignment against the enrollment **at that event**, not the final enrollment, or old assignments appear corrupt after a legitimate rotation. The replacement command must reject active authority, wrong generation, duplicate other slot, invalid service principal, and pending work, and must leave old committed receipts recoverable. No automatic disconnect takeover is implied.
- A wait-only round's `wait_event_id` schema constraint can be preserved compatibly by migration040 renaming the column to `completion_event_id` (SQLite updates the original CHECK); adding `settlement_kind` lets terminal views source their frozen time from either the existing wait Event or a selected typed speech Event. This closes the identified direct RP proposal bypasses in the exposed controller surface, but other internal source-command families are not claimed to be covered.
- If a non-round Event moves the head after a speech selection but before typed acceptance, retry now marks the round stale and frees its branch slot. If the selected `RPSpeak` command already committed, the original exact key drains and settles even after response loss. This prevents a permanent `advancing` slot after an unaccepted child loses its baseline.
